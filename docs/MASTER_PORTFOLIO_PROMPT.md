4. Backend authentication endpoints.
5. Password hashing and verification.
6. Authentication middleware.
7. Protected API routes.
8. Role and permission checks.
9. Token creation and validation.
10. Logout and session invalidation.
11. Token expiry and refresh, if supported.

Document this request flow when applicable:

User → Login interface → HTTPS request → Backend validation → Password hash verification → Token/session creation → Authenticated request → Authorization check → Protected resource.

Security requirements:

- Never store plaintext passwords.
- Use Argon2id or bcrypt for password hashing.
- Never hardcode secrets.
- Store backend secrets in environment variables.
- Never expose private environment variables through frontend code.
- Validate and sanitize inputs.
- Use HTTPS in production.
- Apply login rate limiting.
- Return generic authentication failure messages.
- Protect against brute-force attempts.
- If JWT is used, validate signature, issuer, audience, and expiration.
- Use short-lived access tokens.
- Implement refresh tokens only when required and rotate them where supported.
- Revoke or invalidate sessions on logout.
- Avoid storing long-lived tokens in localStorage.
- Prefer secure HttpOnly, Secure, SameSite cookies where supported by the architecture.
- Implement CSRF protection when cookie-based authentication requires it.

If an external authentication provider already exists, inspect and preserve its actual implementation.

Create `docs/AUTHENTICATION.md` when relevant. Document architecture, components, API endpoints, login request/response examples, credential handling, token lifecycle, protected routes, logout, security controls, and known limitations.
